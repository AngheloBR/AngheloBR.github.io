What actually changes on your server

No black box. This is the delta between a stock VPS and the one I hand back. Each line maps to a page in the report.

server.conf · stock → hardened −6+8
1 # access
2−PermitRootLogin yes
2+PermitRootLogin no
3−PasswordAuthentication yes
3+PasswordAuthentication no
4+AllowUsers deploy # sudo, ed25519 key
5 # network
6−ufw: inactive
6+ufw: active · default deny incoming · allow 22, 80, 443
7−fail2ban: not installed
7+fail2ban: sshd jail · 5 retries → 1h ban
8 # maintenance
9−unattended-upgrades: not configured
9+unattended-upgrades: security updates, daily
10−docker: not installed
10+docker + compose: installed · DOCKER-USER chain wired to ufw # Standard+
11+report.pdf: every change, with rollback notes
Heads-up: Docker bypasses UFW. Docker writes its own iptables rules, so a container's published port is reachable from the internet even while ufw says "deny". Standard and up wire the DOCKER-USER chain so the firewall stays in charge.

Access sshd_config

Passwords get brute-forced all day, every day. Keys don't. Root goes away and a named sudo user takes its place, so every action has an owner.

Network ufw · fail2ban

Default deny means any new service you install is closed until you decide to open it. Fail2Ban bans the hosts that keep knocking.

Maintenance unattended-upgrades

Security patches land on their own. You don't have to SSH in at 2 a.m. because a CVE dropped.

Paper trail report.pdf

Every command, why it ran, and how to undo it. If you ever need to move to another provider, you can redo the whole thing yourself.
